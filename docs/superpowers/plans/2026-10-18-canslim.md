# CANSLIM 분석 (스크리너 프로젝트 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 매일 장 마감 뒤 보통주 전체의 CANSLIM 7항목 판정·점수를 계산해 CH 에 저장하고, stock_api GraphQL 과 웹 `/screener` 에서 목록·점수표로 보여준다.

**Architecture:** 순수 판정 함수(`apps/collector/canslim/rules.py`) ← 하루치 조립(`compute.py`) ← CH 입출력(`repositories/clickhouse_canslim.py`) ← Celery 태스크(일일 파이프라인 끝 + 토요일 재무 뒤 + 60일 백필). stock_api 는 서비스(`services/canslim_query.py`)가 CH·PG 를 읽어 GraphQL 로. 웹은 api → 페이지 → 컴포넌트.

**Tech Stack:** Python 3.12, clickhouse-connect, Celery, Strawberry GraphQL, React 18 + TS + Tailwind, lightweight-charts 4.2.3.

**Spec:** `docs/superpowers/specs/2026-10-18-canslim-design.md`

## Tasks (각 Task = 실패 테스트 → 구현 → 통과 → 커밋, 백엔드는 `cd backend`)

### Task 1: 판정 규칙(순수 함수) — `apps/collector/canslim/rules.py`
- 상태 상수 `PASS=1, FAIL=0, NA=-1, PENDING=-2`, 가중치 `WEIGHTS={"c":20,"a":15,"n":15,"s":10,"l":20,"i":10,"m":10}`, 기준 상수(`C_MIN_GROWTH=25`, `A_MIN_CAGR=25`, `A_MIN_ROE=17`, `N_MIN_RATIO=0.85`, `S_MIN_RATIO=1.0`, `L_MIN_RS=80`, `I_MIN_BUY_DAYS=10`, `M_MAX_DIST=5`, `LIQ_MIN_VALUE=1e9`, `LIQ_MIN_PRICE=1000`).
- `Verdict(status, value=None, extra=dict)`.
- `standalone_quarters(rows[(yymm, eps)], settle_month, cumulative) -> {yymm: eps}` — 누적이면 회계연도 첫 분기(결산월+3)는 그대로, 나머지는 3개월 전 누적값을 뺀다(없으면 제외).
- `eval_c(quarters, settle_month, cumulative: bool|None)` — None → PENDING. 최근 분기 vs 12개월 전 분기, 전년 ≤0 & 올해 >0 = 흑자 전환 PASS.
- `eval_a(annual[(yymm, eps, roe)])` — 최근 4개, 매년 증가 + CAGR ≥ 25 + ROE ≥ 17.
- `eval_n(highs, closes)` (≥60봉), `eval_s(closes, volumes)` (≥51봉), `rs_raw(closes)` (≥253봉), `rs_percentiles({ticker: raw}) -> {ticker: 1..99}`, `eval_l(rs)`, `eval_i(nets)` (≥15일), `market_state(closes, volumes) -> MarketState(close, ma50, ma200, dist_days, status, passed)` (≥200봉), `is_liquid(closes, volumes)`, `score(verdicts) -> (score, pass_count)`.
- Test: `tests/test_canslim_rules.py` — 경계값·부족·흑자 전환·누적 변환(결산월 12·3)·백분위 동률·분산일·M 3상태·점수.

### Task 2: 하루치 조립 — `apps/collector/canslim/compute.py`
- `compute_day(as_of, universe[(ticker, name, market)], profiles{ticker: (sector_m, settle_month)}, bars{ticker: [(date, high, close, volume)]}, index_bars{market: [(close, volume)]}, investor{ticker: [net]}, fundamentals{ticker: {"Y": [...], "Q": [...]}}, q_cumulative) -> (rows[dict], markets[dict])` — RS 백분위·업종 RS 순위(sector_m 중앙값, 1=최강)까지. 종목 단위 예외는 건너뛰고 로그.
- Test: `tests/test_canslim_compute.py` — 가짜 3종목·2시장으로 행 값.

### Task 3: CH 입출력 — `apps/collector/repositories/clickhouse_canslim.py`
- DDL `canslim_daily`·`canslim_market`(스펙 3절), `ensure_canslim_tables`, `load_bars(as_of, days=400)`, `load_index_bars(as_of)`, `load_investor(as_of)`, `load_fundamentals()`, `trading_dates(as_of, n)`, `latest_trading_date()`, `upsert_rows(rows)`, `upsert_markets(markets)`.
- Test: 가짜 CH + 로컬 CH 임시 DB.

### Task 4: 태스크 — `apps/collector/tasks/canslim.py`
- `collector.compute_canslim(as_of=None)`, `collector.backfill_canslim(days=60)`. `FUNDAMENTALS_Q_CUMULATIVE` 읽기(true/false/미설정 None). 일일 파이프라인 끝 단계 추가, beat 토 10:40 `compute_canslim`, celery include.
- Test: `tests/test_canslim_task.py`.

### Task 5: stock_api 조회 서비스·GraphQL
- `apps/stock_api/services/canslim_query.py`: `latest_date()`, `markets()`, `screen(market, min_pass, required, sort, liquid_only, limit, offset)`, `score(ticker)`(+60일 추이), 항목 설명 상수·표시 문자열. 이름·업종명은 PG.
- `graphql/types.py`·`schema.py`: `canslimMarket`, `canslimScreen`, `canslimScore`.
- Test: `tests/test_canslim_query.py`(가짜 CH·PG 함수).

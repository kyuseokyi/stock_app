# 웹·앱 메뉴 통일 (홈 · 커뮤니티 · 게임 · 내정보) — 설계

- 날짜: 2026-10-15
- 요청: "메뉴를 웹과 앱을 동일하게 했으면 하는데 어떤게 좋을까?" → 선택한 안: "4개 통일 (Recommended)"
- 이전 상태: 웹은 상단 메뉴가 커뮤니티 · 게임 2개, 앱은 하단 탭이 홈 · 블로그 · 게임 · 내정보 4개였다.

## 결정
- 웹과 앱의 메뉴 이름과 순서를 **홈 · 커뮤니티 · 게임 · 내정보**로 맞춘다.
- 앱은 "블로그" 탭의 이름만 "커뮤니티"로 바꾼다. 라우트 파일(`(tabs)/blog.tsx`)은 그대로 둔다.
- 웹 경로

  | 메뉴 | 경로 | 내용 |
  |---|---|---|
  | 홈 | `/` | 📌 추천 글(`GET /blogs?featured=true`). 앱 홈과 같은 내용 |
  | 커뮤니티 | `/community` | 첫 게시판으로 이동(기존 HomePage 동작). `/boards/:id`, `/posts/:id`도 커뮤니티로 본다 |
  | 게임 | `/game` | 변경 없음 |
  | 내정보 | `/me` | 로그인 전에는 로그인 버튼(LoginModal). 로그인 후에는 닉네임, 로그아웃, 회원 탈퇴, 게임 바로가기 |

- 웹 배치
  - 데스크톱(sm 이상): 헤더에 상단 메뉴 4개를 둔다.
  - 모바일 폭(sm 미만): 상단 메뉴를 숨기고, 앱과 같은 **하단 고정 탭바**를 둔다(아이콘과 라벨, safe-area 반영).
  - 커뮤니티 섹션에서는 지금처럼 게시판 칩을 보여 준다.
  - 헤더 오른쪽의 로그인 버튼과 닉네임 메뉴는 그대로 둔다(데스크톱 동선 유지).
- 게임 화면(모바일 폭): 하단 고정 주문바를 탭바 바로 위로 올린다(`bottom` = 탭바 높이 + safe-area). 본문 아래 여백도 같은 만큼 늘린다.

## 회귀 방지
- 기존 URL(`/boards/:id`, `/posts/:id`, `/game`, `/auth/complete`)은 그대로 동작한다.
- 동작이 바뀌는 곳은 `/` 하나다.
  - 이전: 첫 게시판으로 이동
  - 이후: 홈(추천 글) 표시. 첫 게시판 이동은 `/community`가 맡는다.
- 백엔드는 바꾸지 않는다. blog의 `featured` 쿼리를 이미 지원한다.

## 검증
- web
  - `npx tsc --noEmit`
  - `vite build --mode development`
  - 로컬 vite에서 데스크톱과 모바일 폭(390px) 스크린샷으로 확인:
    - 탭 이동
    - 활성 표시
    - 게임 주문바와 탭바가 겹치지 않는지
- app: `tsc`, `jest`, 실기기에서 탭 라벨 확인

# 데일리 코치 지지·저항 추천값 채우기 — 설계

- 날짜: 2026-10-15
- 요청: "① 지지·저항 추천값 채우기 진행해줘". 방식은 앞서 제안한 "최근 고점·저점 + 여러 번 닿은 가격대"다.
- 선행: `2026-10-12-trading-game-phase5a-coach-nudge-design.md`. 이 문서는 지지·저항을 수동 입력하는 필드를 정의한다.
- 배경: 관리자가 손으로 입력하다 보니 시드 예시값(71,000/73,500)이 그대로 남았다. 그 결과 지지·저항선이 차트 밖에 그려졌다.

## 범위
- admin 데일리 코치의 지지선·저항선 입력 옆에 **"추천값 채우기"** 버튼을 둔다.
- 버튼은 **폼만 채운다**(저장·발행 안 함). 관리자가 확인한 뒤 기존 버튼으로 임시저장하거나 발행한다.
- 코치 메시지 DTO, WS payload, 웹·앱 표시는 바꾸지 않는다. 이번 작업은 추가만 한다.

## API
`GET /api/game/admin/coach-levels/suggest?season_id=&target_date=&coach_type=` (관리자 전용)

| 상황 | 응답 |
|---|---|
| 정상 | 200 `{ticker, basis_end, bars, last_close, support, resistance}` |
| 시즌 없음 | 404 |
| 일봉 없음·CH 장애 | 503 "일봉 데이터를 불러올 수 없어요." |

- `support`와 `resistance`는 각각 `{price:int, touches:int, basis:str}`이거나 `null`이다.
- 종목은 **선택한 시즌의 ticker**를 쓴다. 활성 시즌이 아니어도 되고, 시즌마다 종목이 다를 수 있다.
- 기준 일봉은 브리핑 종류에 따라 다르다.

  | 브리핑 | 사용하는 일봉 | 이유 |
  |---|---|---|
  | MORNING | `target_date` **전날까지** | 장 시작 전 브리핑이고, 전날 밤에 미리 쓰는 경우도 있다 |
  | EVENING | `target_date` **당일까지** | 당일 일봉이 없으면 전날까지만 쓴다 |

## 계산 (순수 함수 `services/sr_levels.py`)
1. **입력 범위:** 최근 60거래일 일봉을 쓴다. 기준가는 마지막 종가다. 10봉 미만이면 지지·저항 모두 `null`이다.
2. **후보 가격:** 확정 스윙만 후보로 쓴다. 고점과 저점을 모두 넣어 역할 전환(깨진 지지는 저항으로, 돌파한 저항은 지지로)도 잡는다.
   - 확정 스윙이란 앞뒤 2봉보다 엄격히 높은 고점이나 엄격히 낮은 저점이다. 마지막 2봉은 아직 확정되지 않았으므로 제외한다.
   - 60일·20일 최고가/최저가는 후보에 넣지 않는다. 좁은 박스권에서는 박스 끝값이 거의 모든 봉에 닿아 진짜 스윙을 늘 이겨 버린다. 그래서 아래 6번의 폴백으로만 쓴다.
3. **가격대 묶기:** 후보를 가격순으로 정렬한 뒤, 묶음 첫 가격에서 ±1.5% 안에 드는 것을 한 가격대로 묶는다. 가격대 값은 묶음 평균이다.
4. **터치 수:** 고가나 저가가 그 가격대 ±1.5% 안에 들어온 봉의 수다.
5. **지지·저항 선택:** 기준가에서 15% 이내인 가격대 중 점수가 가장 높은 것을 고른다. 기준가 아래는 지지, 위는 저항이다.
   - 점수 = **터치 수 × (1 − 거리/15%)**. 점수가 같으면 기준가에 가까운 쪽을 고른다.
   - 거리 가중이 필요한 이유: 실데이터에서 삼성이 2026-10-08~13에 27만→23만 원대로 급락했다. 터치 수만 보면 +13% 위의 오래된 매물대(266,000원, 24회 터치)가 뽑혔다. 거리 가중을 넣으면 +4.5% 위의 깨진 지지(245,000원, 17회 터치)가 뽑힌다.
6. **폴백:** 후보가 없으면 확정된 20거래일 최저가(지지) 또는 최고가(저항)를 쓴다. 단, 15% 이내일 때만이다.
   - 극값이 마지막 2봉에서 나왔으면 쓰지 않고 `null`을 돌려준다. 신고가 돌파 중이면 저항이 없고, 하락 중이라 저점이 아직 확정되지 않았으면 지지가 없다. 없는 가격대를 지어내지 않는다.
7. **호가 반올림:** KRX 호가단위(2023-01 통합 기준)로 반올림한다.

   | 가격 | 호가단위 |
   |---|---|
   | 2,000원 미만 | 1원 |
   | 5,000원 미만 | 5원 |
   | 20,000원 미만 | 10원 |
   | 50,000원 미만 | 50원 |
   | 200,000원 미만 | 100원 |
   | 500,000원 미만 | 500원 |
   | 그 이상 | 1,000원 |

   - 반올림 결과 지지가 기준가 이상이 되면 한 호가 내린다.
   - 저항이 기준가 이하가 되면 한 호가 올린다.
   - 이 보정으로 **0 < 지지 < 기준가 < 저항**이 항상 성립한다. admin 검증(지지 < 저항)과도 맞는다.
8. **근거 문구 예**
   - "최근 60거래일 저점권 · 3회 터치"
   - "최근 60거래일 이전 저점권(깨진 지지) · 17회 터치"
   - "최근 60거래일 매물대 · …": 고점과 저점이 섞인 가격대
   - "최근 20거래일 최저가": 폴백
9. **실데이터 확인(삼성, 운영 일봉)**

   | 기준일 | 종가 | 지지 | 저항 |
   |---|---|---|---|
   | 10/14 | 234,500 | 224,000 | 245,000(깨진 지지) |
   | 10/06 | 272,500 | 266,000 | 274,000 |
   | 09/28 | 270,000 | 262,000 | 274,000 |

## admin UI
- 지지·저항 입력 위 오른쪽에 "추천값 채우기" 버튼을 둔다. 불러오는 중이거나 저장 중이면 비활성이다.
- 응답이 온 쪽만 채운다. `null`인 쪽은 기존 값을 그대로 둔다.
- 입력칸 아래에 근거 문구를 회색으로 보여 준다. 추천이 없는 쪽은 "추천 없음"으로 표시한다.
- 실패하면 토스트로 알린다.

## 테스트
- 순수 함수
  - 가격대 묶기와 터치 수
  - 지지·저항 선택과 폴백
  - 신고가일 때 저항 `null`
  - 데이터 부족이면 `null`
  - 호가 반올림과 경계
  - 불변식: 지지 < 기준가 < 저항, 기준가와 15% 이내
- 라우터: fetch를 주입한다(CH·KIS 호출 없음).
  - MORNING과 EVENING의 기준일 차이
  - 시즌 없음 404, 데이터 없음 503, 비관리자 403

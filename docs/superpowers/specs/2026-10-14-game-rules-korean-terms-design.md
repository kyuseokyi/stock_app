# 게임 규칙 화면 + 한국어 방향 용어(상승/하락) + 베팅 심리 인원 표시 설계 스펙

> 작성일: 2026-10-14 · 상태: 승인됨(사용자: "게임 규칙을 사용자가 볼수 있도록 해야할것같아. 예를 들면 수수료라던지" → "유저배팅심리란?" → "왜 롱 숏이라는 용어를 사용한거지 한국 시장에 어울리는 용어는 없을까?" → "①로 진행해줘")

## 1. 방향 용어 — 화면 표시만 상승/하락 (API·DB `LONG`/`SHORT` 불변)
- 표시 함수 하나로 모은다: web `lib/side.ts`·mobile `features/game/lib/side.ts` — `sideLabel('LONG')='상승'`, `sideLabel('SHORT')='하락'`.
- 주문 버튼: `🔴 상승에 걸기` / `🔵 하락에 걸기`(BUY/SELL·괄호 보조 문구 제거).
- 베팅 심리 바: `🔴 상승 70%` / `🔵 하락 30%` + 바 아래 `보유 중 N명 기준 · 5초마다 갱신`(N=0 이면 기존 "아직 포지션이 없어요").
- 포지션 카드: `상승 2배`(기존 `LONG x2배`).
- 그 밖에 화면에 노출되는 Long/Short/LONG/SHORT/BUY/SELL/롱/숏(토스트·넛지·퀘스트 문구·명예의 전당 등, 백엔드가 내려주는 사용자 문구 포함)도 같은 규칙으로 바꾼다. 코드 주석·식별자는 그대로.

## 2. 베팅 심리 인원
- WS `sentiment` 메시지에 `total`(보유 중 포지션 수 = 보유 인원, 1인 1포지션) 필드 추가. 기존 `long_pct`·`short_pct` 불변(구 클라이언트 호환).

## 3. 규칙 API `GET /api/game/rules`(공개, 인증 불필요)
값은 실제 계산에 쓰는 상수에서 직접 가져온다(문구에 숫자 하드코딩 금지):
```json
{
  "initial_cash": 10000000,
  "min_order_amount": 100000,
  "max_open_positions": 1,
  "trading_windows": [["09:00","15:30"],["16:00","20:00"]],
  "leverages": [1, 2, 5],
  "leverage_unlock": {"5": "academy"},
  "fee_roundtrip_pct": 0.03,
  "margin_call_roi_pct": -80,
  "sentiment_interval_sec": 5,
  "rewards": { "weekly": [], "monthly": [], "streak": {} }
}
```
- 출처: `INITIAL_CASH`, `order_engine.MIN_ORDER_AMOUNT`, `ALREADY_OPEN` 규칙(1), `market_clock.load_windows()`, 허용 배율(주문 스키마/엔진의 실제 허용 값), 5x 해금 조건(아카데미), `pricing.FEE_ROUNDTRIP_PCT`, `pricing.MARGIN_CALL_ROI_PCT`, `ws_gateway.SENTIMENT_INTERVAL`, `game_settings_service`(reward-config 와 같은 값).
- 테스트: 응답 값 == 상수.

## 4. 규칙 화면(web 모달 `GameRulesModal`, mobile 바텀시트 `rules-sheet`)
섹션(값은 `/rules` + 활성 시즌 정보, 실패 시 "규칙을 불러오지 못했어요" + 다시 시도):
1. **💰 시작과 주문** — 시즌 시작 자본금, 비중(자본금 중 거는 비율), 최소 주문, 동시 보유 1개(청산 후 새로), 거래 시간(KST).
2. **📈 상승·하락과 배율** — 상승에 걸면 주가가 오를 때, 하락에 걸면 내릴 때 수익. 손익(%) = 주가 변동률 × 배율 − 수수료. 예시 표(주가 +1% → 1배 +1%·2배 +2%·5배 +5%, 반대로 움직이면 같은 크기로 손실). 5배는 아카데미 통과 후.
3. **🧾 수수료와 청산** — 왕복 수수료 0.03%가 진입 즉시 반영 → "진입가와 현재가가 같아도 −0.03%에서 시작해요". 청산 종류: 직접 청산 / 손절·익절 / 자동 청산(수익률 −80%) / 시즌 종료 일괄 청산. 자동 청산 이유("건 금액보다 더 잃지 않도록"), 배율별 자동 청산되는 주가 변동(1배 약 −80%, 2배 −40%, 5배 −16%; 하락에 걸었으면 반대 방향). 손절·익절 %는 주가 기준(배율 미반영), 5배 손절 −20%는 자동 청산이 먼저.
4. **🏆 시즌·랭킹·보상** — 시즌 기간(월간/분기)·종료일, 종료 시 남은 포지션은 종가로 일괄 청산 → 명예의 전당(상위 100). 주간(분기 시즌이면 월간도) 랭킹 1~3위 보상 금액·조건(그 기간에 새 주문 1회 이상, 시즌 마지막 주/달은 기록만). 연속 출석 3·7·14·30일 보상(시즌당 1회).
5. **📊 유저 베팅 심리** — 지금 시즌 보유 중인 포지션의 상승/하락 비율(인원 기준, 금액·배율 무관), 5초마다 갱신, 실제 시장 수급 지표가 아님.

진입점(비로그인도 열람 가능):
- 게임 헤더 칩 줄(랭킹·퀘스트·퀴즈) 끝 `📖 규칙`.
- 주문 패널 안내 줄 끝 `수수료 0.03% 포함 · 규칙 보기` 링크(값은 `/rules`).

## 5. 검증
- backend: `/rules` 값=상수, sentiment `total`, 사용자 노출 문구 회귀(기존 테스트 기대 문구 갱신).
- web tsc·build, mobile tsc·jest(side 라벨·규칙 문구 순수 함수 테스트).
- 화면 확인: web 규칙 모달·버튼·심리 바, 에뮬레이터 있으면 모바일.
- 문서: README 게임 섹션에 `/rules`·용어 규칙 한 줄.

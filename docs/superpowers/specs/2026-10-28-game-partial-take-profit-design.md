# 차트 게임 부분 익절 · 원금 회수 설계 (2026-10-28)

> 요청: "게임에서 익절할 때 부분 익절도 추가. 원금 회수 후 수익금으로 홀딩."
> 이전 설계(2026-10-12 phase3 §범위 밖 "추가진입/부분청산")를 이 문서가 대체한다 — 부분 청산만, 추가 진입은 여전히 범위 밖.

## 1. 동작

| 버튼 | 요청 `portion` | 청산 비율 f | 결과 |
|---|---|---|---|
| 익절하기 / 손절하기 / 청산하기(기존) | `all`(또는 본문 없음) | 1 | 지금과 같음 — 전량 청산 |
| ½ 절반 익절 | `half` | 0.5 | 원금의 절반 청산, 나머지 보유 |
| 원금 회수 | `principal` | 1 / (1 + r/100) | 돌려받는 돈 = 지금 원금(size_amount), 남은 포지션의 평가금 = 수익금 |

- r = 수수료를 뺀 ROI(%) = `pricing.compute_roi_pct`. 부분 청산은 **r > 0(수익 상태)에서만** 허용(`NOT_IN_PROFIT` 409).
- 닫는 원금 `close_size = round(size × f, 0.01)`, 남는 원금 `remain = size − close_size`(따로 반올림하지 않음 — 1원 오차 방지). `remain > 0` 이어야 함.
- 남는 원금에는 최소 주문 10만 원 하한을 **적용하지 않는다**(진입 규칙일 뿐. 원금 회수는 보통 남는 금액이 작다).
- 진입가·레버리지·손절가·익절가는 남은 포지션에 그대로. "원금 회수" 뒤 최대 손실 = 남은 원금(= 수익금) — 원금은 지켜진 상태.
- 원금 회수를 두 번 하면 두 번째는 "남은 원금"을 회수(그때의 size_amount 기준).

## 2. 서버

- `POST /api/game/positions/{id}/close` 에 선택 본문 `{ "portion": "all" | "half" | "principal" }`. 본문이 없으면 `all`(옛 앱 호환).
- 부분 청산 = 새 함수 `order_engine.partial_close_position`. 기존 `close_position` 시그니처는 유지(자동 청산·시즌 종료 공용).
- **경쟁 상태**: 부분·전량 청산 모두 조건부 UPDATE 에 `size_amount = 읽은 값` 을 넣는다. 자동 청산이 옛 크기로 지급하거나 두 번 누른 부분 청산이 겹치면 한쪽만 성공, 나머지는 409.
- 기록: 부분 청산마다 `game_trades` 1행(`size_amount = close_size`, 사유 `PARTIAL_TP`(절반) / `PRINCIPAL_OUT`(원금 회수)). 스키마 변경 없음.
- 계좌: 현금 += close_size + pnl. `total_asset` = 현금 + 남은 포지션 평가금, `current_roi`·`max_roi` 도 그 값(기존 `ranking_service.compute_live_roi` 재사용) — 부분 청산 직후 순위가 떨어지지 않게.
- `total_trades`/`win_trades` 는 **최종(전량) 청산 때 1회만**. 승패 = 그 포지션 `game_trades` pnl 합계 > 0. → 자동 청산·시즌 종료도 자동으로 맞음.
- 집계 제외: MBTI 등 `game_trades` 를 "거래 1건"으로 세는 곳은 부분 청산 사유를 뺀다. 넛지·화면 라벨은 사유별로.
- 응답: 기존 `OrderResultResponse` + `realized_pnl`(이번 청산 실현 손익), `returned_amount`(현금으로 돌아온 금액). 부분 청산이면 `status = OPEN`, `size_amount` = 남은 원금, `roi_pct`/`pnl_amount` = 남은 포지션 평가.
- 규칙 API 에 `partial_close: true` — 클라이언트는 이 값이 true 일 때만 버튼을 보인다(서버·웹이 같은 push 에서 병렬 배포되므로, 옛 서버에 `half` 를 보내 전량 청산되는 일을 막음).

## 3. 클라이언트(웹·앱 같은 동작)

- 포지션 카드: 수익 상태이고 `partial_close` 이면 기존 익절 버튼 아래에 [½ 절반 익절] [원금 회수] 두 버튼.
- 지지·저항 알림 시트/모달: 익절 버튼 옆(수익 상태일 때)에 같은 두 버튼. [✊ 홀딩] 은 그대로.
- 원금 회수 버튼 보조 문구: "원금 ○○원 회수 · 수익 ○○원은 계속 보유"(순수 함수로 계산, 현재가 기준 미리보기).
- 스토어 `closePosition(portion)`: 응답 `status === 'OPEN'` 이면 포지션을 응답 값으로 갱신, 아니면 지금처럼 `null`.
- 규칙 화면: "직접 청산 — 원할 때 즉시 전액 청산" → 전량·절반·원금 회수 안내로.

## 4. 정한 기본값(바꿀 수 있음)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 부분 비율 | 50% 하나 | 버튼 수를 줄임. 25·75% 는 필요하면 추가 |
| 허용 조건 | 수익 상태(수수료 뺀 ROI > 0)만 | 요청이 "익절" — 손실 상태 분할 손절은 범위 밖 |
| 남은 금액 하한 | 없음(> 0) | 원금 회수가 대부분 막히지 않게 |
| 거래 수·승률 | 포지션당 1회, 합계 손익으로 승패 | 부분 청산으로 승률 부풀리기 방지 |

## 5. 테스트

절반 청산 / 원금 회수(현금 증가 = 원금, 남은 평가금 = 수익) / 손실 상태 거부 / 크기가 바뀐 뒤 옛 크기로 전량 청산 시 0행 / 부분 뒤 최종 손실이어도 합계 수익이면 승 / total_trades 1 증가 / MBTI 에서 부분 기록 제외 / 본문 없는 요청 = 전량.

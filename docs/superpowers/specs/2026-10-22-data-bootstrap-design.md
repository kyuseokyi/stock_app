# 초기 데이터 준비(부트스트랩) 작업 설계

- 작성: 2026-10-22 · 상태: 승인(사용자 "차트 패턴 끝나고 이어서 만들어줘" — 제안 내용 그대로)
- 배경: 2026-10-22 운영 서버에서 사람이 명령을 하나씩 실행하다 순서가 꼬임(재무 수집 전에 조건검색 백필 → 재무 값 비어 있음), 관리자 잠금에 막혀 재계산 누락, 서버에 `uv` 없음, 장중 백필로 미완성 봉 적재. 새 운영 서버를 만들 때 "env 준비 → 배포 → 버튼 한 번"으로 끝내는 것이 목표.

## 1. 범위
- Celery 태스크 `collector.bootstrap_data(months=37)` — 아래 단계를 **차례로** 실행(앞 단계가 끝나야 다음). 각 단계는 이미 멱등.
- 관리자 작업 버튼 '초기 데이터 준비'(기존 admin_jobs 틀) + 확인 문구 + 시간대 차단 + 단계별 진행 표시.
- 일봉 백필 끝 날짜를 **마지막 확정 거래일**로(장중 미완성 봉 방지) — `backfill_all_daily` 에도 적용.
- 문서: `docs/server_setup.md` 에 새 서버 절차, `backend/.env.example` 운영 필수 값 점검(`FUNDAMENTALS_Q_CUMULATIVE=true` 등).
- 범위 밖: 미국 개별 종목, 게임 데이터, 단계별 재시작 버튼(전체를 다시 눌러도 멱등이라 대신함).

## 2. 단계(순서 고정)
| # | 키 | 내용 | 실패 시 |
|---|---|---|---|
| 1 | `daily_backfill` | 전종목 일봉 `months` 개월(종목 마스터 재로드 포함), 끝 날짜 = 마지막 확정 거래일 | **중단**(뒤 단계는 `skipped`) — 일봉 없이는 계산 무의미 |
| 2 | `indices_kr` | 국내 지수 | 계속 |
| 3 | `indices_us` | 미국 지수·환율 | 계속 |
| 4 | `investor` | 투자자별 순매수(최근 ~30거래일) | 계속 |
| 5 | `fundamentals` | 재무(연간·분기) | 계속 |
| 6 | `ipo` | 공모주 일정 | 계속 |
| 7 | `macro` | 거시 지표(FRED 키 없으면 건너뜀 결과) | 계속 |
| 8 | `canslim` | CANSLIM 60일 백필 | 계속 |
| 9 | `market_groups` | 시장 그룹 60일 백필 | 계속 |
| 10 | `screener` | 조건검색 60일 백필 | 계속 |
| 11 | `patterns` | 차트 패턴(최신일) | 계속 |

- 계산 단계(8~11)는 수집 단계(1~7) **뒤**에만 — 오늘 겪은 "재무 전에 백필" 문제를 구조로 막는다.
- 단계 결과 판정은 일일 파이프라인과 같은 규칙(예외 또는 결과 dict 의 `error` 키 → 실패).

## 3. 마지막 확정 거래일
- KST 기준 지금이 평일 20:30 이후면 오늘, 아니면 직전 평일(공휴일은 KIS 가 빈 응답이라 문제없음). 일일 파이프라인 시각(20:30, NXT 애프터마켓 20:00 마감 뒤)과 같은 기준.
- `backfill_all_daily(months, …, end=None)` — `end` 미지정이면 이 날짜. 기존 호출(인자 없이)도 장중 미완성 봉을 넣지 않게 된다.

## 4. 시간대 차단
- KIS 대량 호출이 매일 20:30 파이프라인과 겹치면 호출 한도를 함께 나눠 쓰게 되고 둘 다 느려진다.
- **시작 차단**: KST 16:00~21:30 에는 시작하지 않음(구현 후 조정: 일봉 백필 1시간+ 가 20:30 파이프라인과 겹치면 두 프로세스 합계 30회/초로 KIS 상한 20회/초 초과)(관리자 실행 시 409 + 안내 "16:00~21:30 에는 정기 수집과 겹쳐 실행할 수 없어요"). 태스크 시작 시에도 같은 검사(큐에서 늦게 시작된 경우).
- **진행 중 차단**: KIS 를 부르는 단계(1~7)를 시작하기 직전에 지금이 20:00~21:30 이면 그 단계부터 `skipped`(사유 기록)로 끝냄 — 다시 누르면 멱등이라 이어서 채워짐.

## 5. 진행 상황
- Redis `admin:bootstrap:progress`(JSON): `{task_id, started_at, finished_at|null, months, end_date, steps: [{key, label, state: pending|running|ok|failed|skipped, seconds, summary, reason}]}` — 단계 시작·끝마다 갱신. 기록 실패는 작업을 막지 않음.
- 관리자 API: 기존 관리자 데이터 현황/작업 응답에 진행 상황을 포함(또는 전용 GET) — 기존 admin_jobs·JobsPanel 의 폴링에 얹는다.
- 관리자 화면(JobsPanel): '초기 데이터 준비' 카드 — 실행 버튼(누르면 확인 창: "KIS 를 대량 호출해 1~2시간 걸려요. 16:00~21:30 에는 실행할 수 없어요. 진행할까요?"), 진행 중이면 단계 목록(상태 아이콘·걸린 시간·요약), 끝나면 마지막 결과 유지.

## 6. 관리자 작업 등록
- `Job("bootstrap", "초기 데이터 준비", "새 서버에 일봉 3년·지수·수급·재무를 받고 지표를 모두 계산해요(KIS 대량 호출, 1~2시간)", "collector.bootstrap_data", "1~2시간", 4시간, {"months": 37})` + 확인 문구 필드, 시간대 차단 필드(이 작업만).
- 중복 실행 방지는 기존 잠금(4시간 TTL) 그대로.

## 7. 테스트
- 단계 순서·실패 격리·`daily_backfill` 실패 시 뒤 단계 skipped, 시간대 차단(시작·진행 중 — 시각 주입), 진행 기록 갱신, 마지막 확정 거래일(평일 20:29/20:30, 주말, 월요일 아침), `backfill_all_daily` end 기본값, admin_jobs 시간대 409, 관리자 화면 타입 검사.

# 키움 테마로 마켓 테마 교체 설계 (ka90001·ka90002, 2026-11-17)

키움 연동 ④-2. 사용자 결정(2026-11-17): **키움 키가 있는 서버(상용)는 테마 분류·구성 종목을 키움 기준으로 교체**, 키 없는 서버(개발)는 지금처럼 KIS 테마 마스터(`theme_code.mst`). 배경: KIS 테마 마스터는 2025-11 이후 갱신이 없어 오래된 테마("2021 신규 상장주" 등)가 섞인다.

## 원칙
- 키움에서 가져오는 것은 **테마 목록(코드·이름)과 테마별 구성 종목**뿐. 테마 순위·등락·기간수익률은 지금처럼 **우리 일봉(`daily_prices`)으로 계산**(다른 화면과 같은 UN 기준). 키움이 주는 등락률은 저장·표시하지 않는다(YAGNI).
- 기존 시장 그룹 계산(`compute_market_groups`·`backfill_market_groups`)과 화면·API 응답 구조는 바꾸지 않는다 — **테마 멤버십의 출처만** 바뀐다.
- 키움 동기화가 실패하면 **마지막으로 성공한 키움 스냅숏**을 계속 쓴다(비우지 않음). 키움 스냅숏이 한 번도 없거나 테마 수가 너무 적으면(기본 100개 미만) KIS 마스터로 계산(안전한 폴백).

## 수집
- `KiwoomClient` 에 `list_themes()`(ka90001 — 전체 테마, 기간·거래소 구분은 명세 확인, 통합 `stex_tp=3` 가능하면 통합) · `theme_members(theme_code)`(ka90002). 경로·body·응답 키·연속조회는 **명세에서 확인**. 시간 제한·미확정 행 같은 숨은 조건은 소량 실측으로 확인.
- 저장: 기존 테마 참조 데이터(구현 시 확인 — `reference_master` 가 적재하는 테마·종목 매핑 테이블과 `market_groups` 가 읽는 곳)에 **출처 구분**을 둔다. 키움 테마 코드는 KIS 코드와 겹치지 않게 접두사(예 `KW`)를 붙인다. 스냅숏은 날짜·출처 단위로 통째 교체(멱등).
- 일정: 20:30 파이프라인에서 `market_groups` 계산 **앞**에 `themes_kiwoom` 단계 — 키움 설정일 때만(아니면 skipped). 호출량은 테마 수(수백) + 1 → 초당 4회면 수 분. 첫 테마에서 rt 오류면 중단(헛호출 방지).
- 초기 데이터 준비: 시장 그룹 60일 백필 **앞**에 같은 단계(키 없으면 건너뜀). 과거 60일 백필도 **현재 키움 스냅숏**으로 계산한다(과거 테마 구성 이력은 없음 — 한계로 문서화).

## 관리자 테마 보정
- 기존 보정(숨김 등)은 테마 코드 기준 → 키움 테마는 코드가 달라 기존 보정이 적용되지 않는다(정상). 관리자 테마 보정 화면은 **현재 계산에 쓰는 출처의 테마 목록**을 보여 주고, 화면 위에 출처(키움/KIS)와 스냅숏 날짜를 표시.

## 소량 실측
- `apps.collector.kiwoom.probe --themes`: 테마 수, 앞 10개(코드·이름·종목 수), 한 테마(첫 번째)의 구성 종목 앞 10개, 응답 행 수·`cont-yn`·오류 코드. 키·토큰 미출력.

## 하지 않는 것
테마 등락률·기간수익률 저장, 과거 테마 구성 이력, KIS·키움 테마 병합, 업종 분류 변경.

## 테스트
클라이언트 body·연속조회, 정규화(코드 접두사·빈 값), 스냅숏 교체 멱등, 출처 선택(키움 성공·실패·스냅숏 없음·테마 수 부족 → KIS), 파이프라인·초기 데이터 준비 단계 위치와 skipped, market_groups 가 선택된 출처의 멤버십으로 계산, 관리자 응답에 출처 표시.

## 반영
상용만 바뀐다. 배포 후 순서: `probe --themes` 실측 → `themes_kiwoom` 수동 1회(태스크) → `backfill_market_groups` → 화면 확인. 문서: `docs/data-collection.md`, `docs/kiwoom_setup_and_dev_spec.md`(④-2), README.

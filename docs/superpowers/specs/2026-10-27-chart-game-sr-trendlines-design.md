## 2. 추세선 계산 — 순수 함수 `trendLines`

앱 `features/game/lib/trend-lines.ts`, 웹 `src/lib/trendLines.ts`(같은 코드).

```
입력: bars[{ high, low }] (오래된 → 최신), 옵션 { pivot = 3, lookback = 120 }
출력: { resistance: TrendLine | null, support: TrendLine | null }
TrendLine = { i1, p1, i2, p2 }  // 캔들 순번(bars 기준)과 가격, i1 < i2
값: valueAt(line, i) = p1 + (p2 − p1) × (i − i1) / (i2 − i1)
```

- 계산 범위: 마지막 `lookback`(120)개 캔들. 보이는 구간이 아니라 **불러온 데이터 기준** — 스크롤해도 선이 바뀌지 않는다.
- 스윙 고점: 앞뒤 `pivot`(3)개 캔들의 고가보다 **크거나 같은** 고가. 같은 값이 이어지면 **나중** 것. 오른쪽에 3개가 없는 최근 캔들은 아직 확정 전이라 제외.
- 저항 추세선 = 가장 최근 스윙 고점 2개(i1 = 앞, i2 = 뒤). 지지 추세선 = 가장 최근 스윙 저점 2개. 2개가 없으면 `null`.
- 선은 i1 에서 시작해 **마지막 캔들까지** 연장해 그린다.

## 3. 지지·저항 목록과 감지

- `SrKey` 를 `'trendHigh' | 'trendLow'` 로 바꾼다(이름: 넓게 `저항 추세선`/`지지 추세선`).
- 목록 = 두 추세선의 **마지막 캔들 위치 값**(`valueAt(line, n−1)`). 역할은 현재가 기준: 값 ≥ 현재가 → 저항, 미만 → 지지(돌파하면 반전).
- 감지(`SrWatcher`)·10분 재알림·"선이 오차보다 크게 뛰면 기준만 다시"는 그대로. 새 봉에서 선 값이 기울기만큼 움직이며, 기울기가 크면 기준만 다시 잡는다.
- 지지·저항 칩이 꺼져 있으면 목록 = [] (선도, 감지도 없음).

## 4. 그리기

- 색: 저항 추세선 `#f59e0b`(주황), 지지 추세선 `#8b5cf6`(보라), 두께 2, 실선. 가격축 라벨·마지막 값 표시 없음.
- 구현: 선 시리즈 하나당 점 3개(i1, i2, 마지막 캔들) — 시각은 그 캔들의 time, 값은 `valueAt`. 마지막 캔들이 i2 면 점 2개.
- 범례: 켜져 있고 선이 있으면 `저항 추세`·`지지 추세` 항목(선 색 견본).
- 앱: 새 메시지 `{ type: 'trend', lines: { color, points: { time, value }[] }[] }` → 페이지가 선 시리즈 2개(미리 만들어 둠)에 `setData`. 지지·저항 가격선(`lines` 의 `axisTitle` 선)은 보내지 않는다. `ChartLine.axisTitle` 은 쓰는 곳이 없으면 제거.
- 웹: 차트 생성 때 선 시리즈 2개를 만들어 두고 `setData`.

## 5. 켜기/끄기

- 차트 설정에 `sr: boolean` 추가, 기본 `true`(웹 `lib/chartPrefs.ts`, 앱 `lib/chart-prefs.ts`, 저장 키는 그대로 — 옛 저장값엔 없으므로 기본 켜짐).
- 칩 이름 `지지·저항`. 웹: 넓은 화면 칩 줄 + 폰 폭 지표 팝오버. 앱: 지표 팝오버. 지표 개수 표시(`지표 N`)에 포함.

- 웹은 앱과 같은 코드(세미콜론만 다름)로 옮기고 타입 검사·빌드·헤드리스 화면 확인.

## 7. 수평선으로 변경(2026-10-27)

사선 추세선이 실제 차트에서 어색해 보여 **수평선**으로 바꾼다. 켜기/끄기 칩·범례·대응 시트/모달·감지기 로직·색·두께 2·자동 범위 제외·축 라벨 없음은 그대로다.

1. **수평 레벨 고르기** — `horizontalLevels(bars, lastPrice, opts?) → { resistance, support }` (`HLevel = { i, price }`). 후보는 마지막 lookback(120)개 안의 스윙 고점(그 캔들 high)·스윙 저점(그 캔들 low) 전부(기존 `swings` 그대로). 저항 = 후보 중 `price ≥ 현재가` 가운데 가장 낮은 가격, 지지 = `price < 현재가` 가운데 가장 높은 가격, 같은 가격이면 더 최근. 없으면 null. 고점·저점을 섞어 고르므로 뚫린 옛 고점은 지지, 깨진 옛 저점은 저항이 된다(역할 반전). 사선용 `trendLines`·`valueAt`·`TrendLine` 은 제거.
2. **지지·저항 목록** — `srLevelsFromHorizontal` 이 저항 먼저 목록을 만든다. **SrKey 는 레벨 가격 기반 `lvl:${price}`**. 키가 '저항/지지' 역할이면 저항을 돌파해 같은 선이 지지가 될 때 키의 가격이 크게 바뀌어 감지기가 기준만 다시 잡고 돌파 이벤트를 놓친다. 가격 키면 같은 레벨이 계속 같은 키라 RESISTANCE_BREAKOUT·SUPPORT_BREAKDOWN 이 정상 발생한다. 이름은 키가 아니라 역할·이벤트 종류에서: `srRoleName(role, short)`(저항선/지지선, 좁게 저항/지지), 시트·모달은 `srEventName(type)`(RESISTANCE_* = 저항선, SUPPORT_* = 지지선). `srName` 은 제거, `srSignature` 는 유지.
3. **그리기** — 선 시리즈 2개 그대로. 점 = `[{ time: bars[h.i].time, value: h.price }, { time: bars[last].time, value: h.price }]`. 없으면 빈 배열. 점 배열이 같으면 다시 보내지 않는 안정화 유지. 범례 문구 `저항선`·`지지선`.
4. **감지 입력** — `srLevelsFromHorizontal(horizontalLevels(bars, price))`, price = lastPrice ?? 마지막 종가. 칩이 꺼지면 빈 목록.

테스트: `horizontalLevels`(가까운 위·아래, 고점·저점 섞임, 같은 가격이면 최근, 후보 없으면 null, lookback 밖 무시, 확정 전 제외), `srLevelsFromHorizontal`(키·역할·색), `SrWatcher` 에 "같은 가격 키가 저항→지지로 바뀌어도 돌파 이벤트" 추가.

### 7-1. 매물대 POC 후보

- 매물대 칩이 **켜져 있을 때만** 보이는 구간 POC 가격(거래량 가장 큰 칸의 가운데 가격)을 수평선 후보에 더한다. 꺼지면 스윙 고점·저점만.
- `horizontalLevels` 의 `opts.poc` 로 받아 스윙 후보와 같은 규칙(현재가 이상 중 최저 = 저항, 미만 중 최고 = 지지)으로 함께 고른다. POC 후보의 시작 순번 i 는 계산 범위 시작 `max(0, n - lookback)`. 가격이 스윙과 같으면 더 최근 i 인 스윙이 우선.
- 값 전달: 앱은 페이지 `VolumeProfile` 이 POC 가 바뀔 때만 `{ type: 'poc', price }` 를 보내고(끄면·칸 없으면 null) `tv-chart` 의 `onPoc` → `candle-chart` 가 종목·단위 키와 함께 보관(전환 직후 옛 값 무시). 웹은 `VolumeProfilePrimitive.onPocChange`(바뀔 때만, requestAnimationFrame, detached 에서 해제) → `TradingChart` 의 `poc` 상태(차트 재생성 cleanup 에서 null).
- 스크롤로 POC 가 바뀌면 새 가격 = 새 키(`lvl:가격`)라 감지기가 기준만 잡아 가짜 돌파·이탈이 없다(sr-watch 테스트로 확인).

### 7-2. 감지는 후보 레벨 전체, 그리기는 가장 가까운 2개

`horizontalLevels` 는 가장 가까운 위·아래 2개(그리기)와 함께 `candidates`(lookback 안의 모든 스윙 고점·저점 + POC, 같은 가격은 하나)를 돌려주고, 감지기에는 `srWatchLevels(candidates, 현재가)` 전체를 넘긴다. 이유: `SrWatcher` 는 목록에서 빠진 키의 상태를 지우므로, 가까운 2개만 넘기면 레벨이 오차띠 안에 붙어 있거나 갭 틱으로 두 레벨을 한꺼번에 넘을 때 보던 레벨이 목록에서 빠지며 상태가 지워지고 새로 들어온 레벨은 기준만 잡아 돌파·이탈 이벤트를 놓친다.

### 7-3. 마지막 캔들이 닿은 지표에 가로선(2026-10-28)

사용자 요청: "마지막 캔들이 해당 매물대poc나 기타 지표의 지지와 저항에 터치 또는 관통 했을때 가로 추세선을 추가."

- 대상: **켜진 지표만** — 매물대 POC(매물대 칩), 5·20·60일선(이동평균 칩), BB 상단·중심·하단(볼린저 칩). 값은 마지막 캔들 위치 값. 지지·저항 칩이 꺼지면 없음.
- 닿음: 마지막 캔들 `저가 − 오차 ≤ 레벨 ≤ 고가 + 오차`(오차 = `srEps` = max(호가, 0.15%)) — 꼬리가 스친 터치와 몸통·꼬리가 뚫은 관통을 함께 잡는다.
- 중복: 호가 반올림 가격이 같으면 먼저 온 것 하나(순서 POC → 이동평균 → 볼린저). BB 중심은 정의상 20일선과 같아 20일선만 남는다.
- 그리기: 그 가격에 **점선(Dotted) 가로 가격선**, 두께 2, 지표 색(POC 는 점과 같게 현재가 이상 주황·아래 보라), 축 라벨 표시. 범례 `○○ 닿음`(점선 견본). 닿은 목록(id·호가 반올림 가격)이 바뀔 때만 다시 그린다.
- 순수 함수 `touchedLevels(last, levels)` — 앱 `features/game/lib/touch-levels.ts`(jest), 웹 `lib/touchLevels.ts`(같은 코드).
- 감지기(대응 시트·모달) 입력은 바꾸지 않는다 — 이동평균·볼린저는 틱마다 값이 움직여 가격 키가 계속 바뀌므로 감지 대상에 넣지 않는다.
- 앱(WebView 차트) 연결은 웹 확인 뒤 같은 규칙으로 한다.

### 7-4. 지지·저항선을 차트 전체 폭으로(2026-10-28)

사용자 요청: "일단 지지나 저항선은 차트 넓이 대로 그려지면 좋겠어."

- §7 의 "그 레벨 캔들부터 마지막 캔들까지" 선 시리즈 대신 **캔들 시리즈의 가격선**(`createPriceLine`, 실선 2, 역할 색 — 저항 주황·지지 보라)으로 그린다. 차트 왼쪽 끝부터 오른쪽 끝까지, 가격축 라벨 표시.
- 가격선은 자동 가격 범위에 들어가지 않으므로(lightweight-charts 4) 먼 레벨도 캔들을 납작하게 만들지 않는다 — 이전 `autoscaleInfoProvider: () => null` 과 같은 효과.
- 고르는 규칙(가장 가까운 위·아래 2개)·감지기 입력(후보 전체)·범례·칩은 그대로. 다시 그리기는 두 가격이 바뀔 때만.
- 웹 `TradingChart` 는 선 시리즈 2개를 없애고 가격선으로, 앱 `candle-chart` 는 `trend` 메시지 대신 `lines`(ChartLine)에 함께 넣는다(페이지의 `trend` 처리는 쓰는 곳이 없어도 남겨 둠 — 빈 목록이면 아무것도 그리지 않음).

## 8. 지지·저항 = 지표 5개, 몸통 기준(2026-10-28)

사용자 요청: "게임에 사용할 지지 및 저항선은 poc매물대와 볼린저밴드 상단 하단, 그리고 5일선 20일선이야 그리고 꼬리는 빼고 몸통이 닿았을 때를 기준으로", "20일선과 bb 중심선은 같다라고 생각하면 될 것 같아".

- **지지·저항 레벨** = 매물대 POC(매물대 칩이 켜져 있을 때만)·5일선·20일선(= BB 중심)·BB 상단·BB 하단의 마지막 캔들 값. 60일선은 제외. 이동평균·볼린저 칩과 무관하게 계산(표시 칩은 곡선을 그릴지만 정함). 지지·저항 칩이 꺼지면 없음.
- 역할: 레벨 ≥ 현재가 → 저항, 미만 → 지지(넘으면 반전).
- **그리기**: 마지막 캔들 **몸통**(시가~종가 ± 오차, 꼬리 제외)이 닿은 레벨만 차트 전체 폭 가격선(실선 2, 지표 색, 축 라벨). 범례 `5일선 지지`·`BB 상단 저항` 식. 같은 호가 가격이면 앞(POC → 5일선 → 20일선 → BB 상단 → BB 하단) 하나.
- **감지(대응 알림)**: 5개 전부를 `SrWatcher` 에 넘긴다. 키 `ind:<id>`(지표 값이 틱마다 오차 안에서 움직여도 같은 선, 오차보다 크게 뛰면 기준만 다시). 판정 가격은 현재가(= 몸통의 종가 쪽)라 꼬리 기준이 아니다. 이벤트에 `name`(20일선 등)을 실어 시트·모달 문구가 "20일선(246,475원) 상향 돌파"가 된다.
- §7 의 스윙 고점·저점 수평선과 §7-3 의 "켜진 지표 꼬리 포함 점선"은 차트에서 쓰지 않는다(`trendLines`·`srWatchLevels` 함수와 테스트는 남겨 둠).
- 순수 함수: `srIndicatorLevels(closes, poc)`·`touchedLevels(last{open,close}, levels)`(앱 `touch-levels.ts`, 웹 `touchLevels.ts`), `srFromIndicators(levels, price)`(`sr-levels`/`srLevels`).

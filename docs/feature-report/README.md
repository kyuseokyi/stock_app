         ├──── REST ────────┼───────────────────┤

  blog :8000      auth :8001      stock_api :8002      trading_game :8003
  게시판·글·댓글   로그인·JWT       GraphQL 시세·스크리너  가상 트레이딩·WS
  SSE·푸시·앱버전  소셜 로그인       관리자 시장 데이터 REST 랭킹·퀴즈·코치

## 남은 일 (코드와 문서 기준)

1. **운영 설정**
   - `.env.production`에 `EXPO_PUBLIC_GAME_API_URL`이 없어서 운영 앱의 게임 탭에 "시즌 준비 중"이 뜹니다.
   - 앱 Drive 백업에 필요한 `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`가 없습니다.
   - FRED API 키를 아직 받지 않았습니다.
2. **실기기 확인**
   - 게임 시트와 WebSocket 재연결, 주도주·조건검색·패턴, 앱 업데이트 시트.
   - 펀드 정기 작업이 앱이 꺼진 상태에서도 실행되는지 측정.
3. **간편 로그인**: 카카오는 웹·앱 모두 성공을 확인했습니다(10-23). 네이버는 키 발급 후 확인과 검수가 남았고, 애플 로그인은 iOS 출시 직전에 붙입니다.
4. **관리자 웹 보완**
   - 회원 목록과 통계 화면이 비어 있습니다.
   - 게시글 상세에 댓글 수정 UI가 없고, 본문을 정화(sanitize)하지 않습니다.
   - 로그인 화면에 기본 계정 안내 문구가 그대로 나옵니다.
5. **앱 내정보**: "이번 시즌 내 순위" 카드와 "준비 중" 4개 항목을 실제 기능과 연결해야 합니다.
6. **iOS**: APNs 설정과 스토어 링크.
7. **새 APK 빌드**: 펀드 계정별 저장 중 `allowBackup=false`는 네이티브 변경이라 새 APK를 설치해야 반영됩니다. 그다음 계정 분리와 재설치 시나리오를 실기기에서 확인해야 합니다.

## 캡처 방법과 개인정보 처리

- **실행 환경**
  - 로컬 백엔드 4개(8000~8003)를 띄우고, SSH 터널로 개발서버 DB(PostgreSQL·ClickHouse)에 붙었습니다.
  - 관리자 웹과 사용자 웹은 Vite 개발 서버로 띄웠습니다.
  - 앱은 Android 에뮬레이터에 개발 빌드를 설치하고 Metro를 8082 포트로 연결했습니다.
- **로그인 계정**: 관리자는 기본 관리자 계정, 앱과 웹은 개발용 닉네임 `test` 계정을 썼습니다.
- **가린 정보**
  - 관리자 로그인 화면의 기본 계정 안내 문구.
  - 댓글 작성자 닉네임 1개(`사용자A`로 바꿈).
  - 앱 랭킹 시트의 다른 사용자 닉네임(흐림 처리).
- **찍지 않은 화면**: 실명, 투자자 번호, 금액이 나오는 **펀드 리포트와 수익 히스토리**. 해당 문서에 글로만 설명했습니다.

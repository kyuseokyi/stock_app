# 1단계. 요구사항과 API 설계 — 코드보다 먼저 종이에

> 목표: 코드를 한 줄도 쓰기 전에 "무엇을, 어떤 주소로, 어떤 결과로" 만들지 정한다. 이 단계가 흐리면 뒤에서 계속 고친다.

## 1-1. 요구사항을 문장으로 쓴다

1. 로그인한 사용자는 게시글을 **저장**할 수 있다.
2. 같은 글을 두 번 저장해도 **하나만** 저장된다.
3. 저장을 **해제**할 수 있다.
4. **내가 저장한 글 목록**을 최신 저장 순으로 볼 수 있다. 목록에는 글 제목이 보인다.
5. 없는 글은 저장할 수 없다.
6. 로그인하지 않으면 아무것도 할 수 없다.
7. 글이 삭제되면 그 글의 저장 기록도 사라진다. 회원이 탈퇴하면 그 회원의 저장 기록도 사라진다.

> 6·7번처럼 **"안 될 때"와 "지워질 때"** 를 미리 적어 두는 게 초보와 숙련자의 차이다.

## 1-2. 어느 서비스에 넣나

| 후보 | 판단 |
|---|---|
| auth (로그인) | ✗ 로그인과 관계없음 |
| **blog (게시판·글·댓글)** | **✓ 게시글에 붙는 기능** — 댓글과 같은 자리 |
| stock_api / trading_game | ✗ 주식·게임과 관계없음 |

→ `backend/apps/blog/` 에 만든다.

## 1-3. 주소(URL)와 메서드 정하기

REST 의 기본 원칙: **주소는 "무엇(명사)"**, **메서드는 "어떻게(동사)"**.

| 요구사항 | 메서드 | 주소 | 성공 응답 |
|---|---|---|---|
| 저장 | `PUT` | `/api/v1/blogs/{blog_id}/bookmark` | `200` + 저장 정보 |
| 해제 | `DELETE` | `/api/v1/blogs/{blog_id}/bookmark` | `204` (본문 없음) |
| 내 목록 | `GET` | `/api/v1/me/bookmarks` | `200` + 목록 |

### 왜 `POST` 가 아니라 `PUT` 인가
- `POST` 는 보통 "새로 하나 더 만들기"다. 두 번 보내면 두 개가 생기는 게 자연스럽다.
- 북마크는 "이 글을 **저장된 상태로 만들어라**" 다. 몇 번을 보내도 결과가 같다(= **멱등**). 이럴 때 `PUT` 이 맞다.
- 덕분에 화면에서 버튼을 두 번 눌러도, 네트워크 재시도로 두 번 가도 에러가 나지 않는다.

### 왜 주소에 `user_id` 가 없나
- "누구의" 북마크인지는 **로그인 토큰**에서 알아낸다. 주소에 `user_id` 를 받으면 남의 번호를 넣어 남의 북마크를 조작할 수 있게 된다.
- 그래서 내 목록은 `/me/bookmarks` 다.

### 기존 주소와 맞추기
댓글이 `/api/v1/blogs/{blog_id}/comments` 이므로 북마크도 `/api/v1/blogs/{blog_id}/bookmark` 로 맞췄다. **새 기능은 옆 기능의 모양을 따라가는 게 원칙**이다(읽는 사람이 덜 헷갈린다).

## 1-4. 실패할 때 응답 정하기

| 상황 | 상태 코드 | 누가 처리하나 |
|---|---|---|
| 토큰 없음·만료 | `401` | `shared/auth.py get_current_user` (자동) |
| 없는 글 저장 | `404` `{"detail": "게시글을 찾을 수 없습니다."}` | 우리가 만들 코드 |
| `blog_id` 가 숫자가 아님 (`/blogs/abc/bookmark`) | `422` | FastAPI (자동) |
| 이미 저장된 글 다시 저장 | `200` (에러 아님) | 우리가 만들 코드 |
| 저장 안 된 글 해제 | `204` (에러 아님) | 우리가 만들 코드 |

## 1-5. 응답 예시를 미리 써 본다

`PUT /api/v1/blogs/12/bookmark` →
```json
{ "id": 3, "post_id": 12, "post_title": "11월 시장 정리", "created_at": "2026-11-09T14:40:00+09:00" }
```

`GET /api/v1/me/bookmarks` →
```json
[
  { "id": 3, "post_id": 12, "post_title": "11월 시장 정리", "created_at": "2026-11-09T14:40:00+09:00" },
  { "id": 1, "post_id": 7,  "post_title": "CANSLIM 이란",  "created_at": "2026-11-08T09:10:00+09:00" }
]
```

이 예시가 5단계의 응답 스키마가 된다. 웹·앱 개발자에게도 이 예시를 먼저 보여 주면 서버 완성 전에 화면 작업을 시작할 수 있다.

## 체크

- [ ] 요구사항 7개를 내 말로 다시 설명할 수 있다.
- [ ] `PUT` 과 `POST` 의 차이를 "버튼 두 번 누르기" 예로 설명할 수 있다.
- [ ] 주소에 `user_id` 를 넣으면 안 되는 이유를 안다.

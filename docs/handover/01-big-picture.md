# 1. 전체 그림 — 무엇이 있고, 서로 어떻게 대화하나

> 목표: 이 문서를 다 읽으면 "stock_app 은 프로그램 몇 개로 이루어져 있고, 화면에서 버튼을 누르면 어디로 요청이 가는지" 를 그림으로 그릴 수 있다.

## 1-1. 이 서비스는 무엇을 하나

한국투자증권(KIS) API 로 **국내 주식 데이터를 매일 모아** 차트·스크리너(종목 찾기)·시장 개요를 보여 주고,
**블로그/커뮤니티**, **가상 주식 트레이딩 게임**, **펀드 리포트 알림**을 웹과 모바일 앱으로 제공한다.
사용자 화면은 3종류다.

| 화면 | 누가 쓰나 | 폴더 |
|---|---|---|
| 일반 사용자 웹 | 일반 회원 | `web_client/` |
| 관리자 웹 | 운영자(관리자 계정) | `admin_web/` |
| 모바일 앱 (iOS/Android) | 일반 회원 | `mobile/` |

## 1-2. 식당에 비유하면

처음엔 이렇게 생각하면 쉽다.

| 식당 | stock_app | 설명 |
|---|---|---|
| 손님이 보는 메뉴판·테이블 | **웹·앱 (프론트엔드)** | 사람이 보는 화면 |
| 주문을 받아 주방에 전달하는 직원 | **API 서버 (FastAPI)** | 화면이 보낸 요청을 받아 처리하고 결과를 돌려준다 |
| 창고·냉장고 | **DB (PostgreSQL · ClickHouse · Redis)** | 데이터를 저장한다 |
| 새벽에 장 보러 가는 직원 | **배치 워커 (Celery)** | 사람이 요청하지 않아도 정해진 시간에 데이터를 모으고 계산한다 |
| 식재료 공급업체 | **외부 API (KIS, FRED, Gemini 등)** | 데이터 원천 |

## 1-4. 백엔드 서비스 한 줄 요약

백엔드는 "서버 하나"가 아니라 **용도별로 나눈 여러 개의 작은 서버(마이크로서비스)** 다. 모두 `backend/apps/` 아래에 있다.

| 서비스 | 폴더 | 로컬 포트 | 운영 포트 | 운영 주소 | 하는 일 |
|---|---|---|---|---|---|
| auth | `apps/auth/` | 8001 | 8001 | `auth.haezean.com` | 로그인(관리자·카카오·네이버·게스트), JWT 발급, 회원 탈퇴 |
| blog | `apps/blog/` | **8000** | **8003** | `blog.haezean.com` | 게시판·글·댓글, 실시간 알림(SSE), 푸시 기기 등록, 앱 버전 정책 |
| stock_api | `apps/stock_api/` | 8002 | 8002 | `api.haezean.com` | GraphQL(종목 검색·차트·스크리너·시장) + 관리자 REST, AI 시황(`apps/ai_analyst/`) |
| trading_game | `apps/trading_game/` | **8003** | **8004** | `game.haezean.com` | 가상 주문/체결, 랭킹, 퀘스트·퀴즈, 실시간 WebSocket |
| collector | `apps/collector/` | (포트 없음) | (포트 없음) | — | Celery 워커·스케줄러(데이터 수집·계산·푸시 발송), `run_game_ws` 실시간 시세 데몬 |
| shared | `shared/` | — | — | — | 모든 서비스가 같이 쓰는 코드(DB 모델·DB 연결·JWT 검증·설정) |

> ⚠️ **포트 주의**: 로컬과 운영의 포트가 다르다. 로컬은 blog=8000·game=8003, 운영 도커(`docker-compose.prod.yml`)는 blog=8003·game=8004. 문서·코드에서 8003 이 나오면 "로컬인지 운영인지" 먼저 확인한다.

## 1-5. 데이터 저장소 3종

| 저장소 | 비유 | 무엇을 저장 | 자세히 |
|---|---|---|---|
| **PostgreSQL** | 장부(엑셀처럼 표) | 회원, 게시판, 글, 댓글, 게임 계좌·거래, 테마 등 "관계가 있는 데이터" | [5장](./05-database.md) |
| **ClickHouse** | 거대한 시계열 창고 | 전종목 일봉(가격·거래량), 지표, 스크리너 결과 등 "날짜별로 쌓이는 대량 데이터" | [5장](./05-database.md) |
| **Redis** | 메모장·우체통 | 캐시, 실시간 시세(틱), Celery 작업 대기열, SSE·WS 메시지 전달 | [5장](./05-database.md) |

## 1-6. 요청 하나가 흐르는 길 (예: 웹에서 댓글 달기)

1. 사용자가 웹 글 상세 화면에서 댓글을 입력하고 "등록"을 누른다.
2. `web_client` 가 `POST /api/v1/blogs/12/comments` 요청을 보낸다. 로그인 토큰(JWT)을 `Authorization: Bearer …` 헤더에 붙인다.
3. 인터넷 → Cloudflare Tunnel → 미니PC 의 blog 서버로 들어온다.
4. blog 서버의 `routers/comments.py` 가 토큰을 확인해 "누가" 썼는지 알아내고, 게시글이 있는지·댓글이 허용된 게시판인지 검사한다.
5. `crud.py` 가 PostgreSQL `blog_comments` 테이블에 한 줄을 추가한다.
6. 서버가 저장된 댓글을 JSON 으로 돌려주고, 화면이 목록에 그린다.

이 흐름을 [4장](./04-server-fastapi.md)(서버) → [5장](./05-database.md)(DB) → [6장](./06-api.md)(API) → [8장](./08-web.md)(웹) → [9장](./09-mobile.md)(앱)에서 실제 코드로 하나씩 따라간다.

## 1-7. 폴더 지도 (루트)

```
stock_app/
├── backend/            # 파이썬 백엔드 전부 (FastAPI 서버들 + Celery)
│   ├── apps/           #   서비스별 코드 (auth, blog, stock_api, trading_game, collector, ai_analyst)
│   ├── shared/         #   공통 코드 (DB 모델, DB 연결, 인증, 설정)
│   ├── alembic/        #   PostgreSQL 테이블 변경 이력(마이그레이션)
│   ├── scripts/        #   일회성 스크립트(시드 등)
│   └── tests/          #   pytest 테스트
├── web_client/         # 일반 사용자 웹 (React + Vite + TypeScript)
├── admin_web/          # 관리자 웹 (React + Vite + TypeScript)
├── mobile/             # 모바일 앱 (Expo / React Native)
├── deploy/             # 운영 배포 설정 (Docker Swarm, K8s)
├── docs/               # 문서 (지금 읽는 handover 포함)
├── scripts/            # 개발 편의 스크립트 (개발 DB 터널 등)
├── .github/workflows/  # 자동 배포 (GitHub Actions)
├── docker-compose.dev.yml   # 로컬용 DB 3종
└── docker-compose.prod.yml  # 운영 서버용 전체 서비스
```

## 직접 해보기

1. `backend/apps/` 폴더를 열어 위 표의 서비스 폴더가 다 있는지 확인한다.
2. `docker-compose.prod.yml` 을 열어 `ports:` 를 찾아 보고, 1-4 표의 운영 포트와 맞는지 확인한다.
3. 1-6 의 6단계를 종이에 그림으로 그려 본다. 다음 장들을 읽으면서 각 칸에 파일 이름을 채워 넣는다.
